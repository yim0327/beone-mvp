## 2026-10-30 · 서비스 후보 취합 구현 · 완료(커밋 전)
- 한 일: 규칙 선택 결과(`RuleSelection`)와 주문 한 건, 같은 카드의 월간 상태로 규칙의 서비스마다 후보·확인 필요·지원 범위 밖 중 하나로 모으는 `CardServiceCandidateCollector`를 `primitive`에, 결과 타입 `CardServiceCandidates`(`Unavailable`·`Collected`)와 `ServiceNeedingConfirmation`·`ConfirmationStage`·`UnsupportedService`·`UnsupportedReason`을 `result`에 추가했습니다. #31 판정기를 규칙 선택 결과에 처음 연결했습니다. 기존 타입은 바꾸지 않았습니다.
- 서비스에서 달라진 점: 선택된 카드 규칙의 서비스들을 개별 후보로 취합할 수 있습니다. 아직 어떤 서비스를 채택할지나 카드 혜택 합계는 정하지 않습니다.
- 지키는 조건: 규칙 사용 불가는 사용 불가 결과로 남고 0원·빈 결과가 되지 않습니다. 분류 우선순위는 지원 범위 밖(한도·선택형) > 규칙 선택 단계 확인 필요 > 전월 실적 미입력·`UNKNOWN` > 판정기 결과입니다. 범위 밖과 선택 단계 확인 필요가 겹치면 범위 밖에 두되 선택 단계 사유 원문을 보존합니다. 후보 목록에는 확정 금액(확정 0원 포함)만 두고, 판정기의 확인 필요는 사유 문자열 그대로 확인 필요로 옮깁니다. 신규 유예 근거는 유예 정의가 확정이고 없거나 해당 서비스가 대상이 아닐 때만 `CONFIRMED_ABSENT`, 그 밖에는 `UNDETERMINED`이며 `PRESENT`는 만들지 않습니다. 조건부 미확정 조건은 원본 그대로 전달하고 해소하지 않습니다. null, 카드 ID 불일치, 음수 실적(모든 경로), 규칙과 맞지 않는 선택 결과는 거부합니다.
- 범위 결정: 처리 원칙은 2026-10-30 사용자 확인(이슈 #33), 분류 우선순위·단일 소속·근거 전달 방식은 2026-10-30 관리자 승인(구현 전 계약 점검). D-13에 #33 범위 기록 1항목을 추가했습니다.
- 남은 제한: 채택·기여액·합계, 한도·선택형 서비스 판정, 한도 차감, 중복 적용, 실적 원장 산출·기간 검증, 신규 유예 기간·간주 실적 판정, `RuleCatalog.select`를 포함한 통합 진입점은 하지 않습니다. 실적이 없으면 실적 조건이 없는 서비스도 확인 필요로 둡니다. 테스트 값은 가상 카드·서비스·업종의 합성 값이며 실제 약관 검증이 아닙니다.
