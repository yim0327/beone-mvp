## 지금 가능한 것

- 네이티브 기기 인증(#22): 지문 또는 기기 PIN을 한 인증 창으로 받습니다(D-08). 인증 수단이 없으면 활성화하지 않고 설정 안내를 합니다.
- 60초 활성 상태(#22): 성공 시 60초 활성, 만료·실패·취소·앱 이탈 시 즉시 비활성, 활성 중 재인증 성공 시 새 60초. 회전 등 화면 구성 변경은 이탈로 보지 않습니다.
- 인증 요청 하나만 진행(#22, **검증용 구현**): 앱 이탈로 취소한 요청은 `정리 중`으로 두고 최종 결과가 올 때까지 새 요청을 받지 않습니다. 응답이 없으면 `정지`로 바꾸고 활성화하지 않습니다. 응답 대기 시간 30초·5초는 debug 실험값입니다.
- 확인 수단(#22): 단위 테스트 84건(가짜 authenticator, 2026-10-31 실행), debug 앱의 **B:ONE 인증 점검** 화면과 debug 전용 관측 로그 `BeoneAuthTrace`(release 미포함, release APK 정적 점검으로 확인)
- 실기기(#22, SM-S942N Android 17 한 대): 구조 도입 전 코드로 1~15번 통과. 지금 코드로 R1~R4·R6~R9와 1~6·8~11·13번 관측상 통과, R5·R10 관측 못 함 — [확인 기록](../../android/device-checklist.md#확인-기록-2026-10-2930-지금-코드-커밋-전)
- WebView 셸(#25): debug는 개발 서버를 열고 신뢰 origin 밖 탐색을 막습니다. release는 웹 주소 미설정으로 아무것도 열지 않습니다. 단위 테스트 16건, release 정적 점검 통과. 실기기 W1~W5 미실행
- 연결 단계: 기기 인증과 WebView는 서로 연결되지 않았고, 웹 브리지·서버 연결도 없습니다.

1. **release 로딩 방식과 신뢰 origin** — 권장안: 앱 에셋(`WebViewAssetLoader`, `https://appassets.androidplatform.net`). PoC에서 동작 확인, 네트워크 없이 origin 고정 가능.
2. **브리지 계약**(PR #28의 B1~B6과, 리뷰·#22 대조에서 나온 활성 중 재인증 처리·하위 프레임 응답·`NO_RESPONSE`·요청 단계 표현) — 프런트엔드와 함께 정해야 합니다. #28 미커밋 수정안의 커밋 여부도 함께 정합니다.
3. **#22 운영 값** — 응답 대기 시간, 정지 뒤 복구 방식, 화면이 보일 때만 인증을 요청하는 조건(RESUMED).
4. **실기기 시험 승인** — #22 16·17번(기기 보안 설정 변경), #25 W2 판정 기준·W3 계열 실행 방식·release 시험용 서명, 기기 설치·실행.
5. **독립 리뷰 요청** — 이전 CodeRabbit 한도 안내에 사용량 기반 과금 가능성이 있어 draft PR 수동 리뷰를 다시 요청하지 않았습니다.
