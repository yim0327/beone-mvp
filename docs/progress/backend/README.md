## 지금 가능한 기능
- `develop` 반영: 카드 규칙·입출력 모델과 검증, 날짜에 맞는 검증 규칙 선택, 공통 API 응답·오류 처리, 서비스 한 건의 정률·정액 계산·대상 금액 상한·원 미만 발생 확인·최소 금액·결제 방식·업종 판정·전월 실적 구간 선택(#21).
- 작업 브랜치(#29): 서비스 하나의 후보 판정, 최종 채택 여부, 실제 기여액을 나눠 담는 결과 타입과 생성 검증.
- 연결 단계: 위 계산과 결과 타입은 서로 연결되지 않았고, 카드별 결과·API·화면·앱에도 연결되지 않았습니다.

## 아직 안 되는 기능
- 주문 한 건의 카드별 혜택 결과(`OrderBenefit` 전체), 채택 결정·기여액 계산, 한도 차감, 중복 적용, 월간 최적화·추천.
- 수동 카드·상태·주문 API, CODEF 연동, 모의 승인.

## 사용자 확인 사항
1. 음수 전월 실적(취소가 승인보다 많은 달)의 구간 판정. 권장안: 실적 조건이 있는 서비스는 미충족, 실적 조건이 없는 서비스(0원 단일 구간)는 조건 없음으로 본다. 확정 전까지 거부합니다.
2. 정액 혜택이 결제 금액보다 클 때 결제 금액으로 줄일지. 권장안: 청구 할인은 결제 금액을 넘지 않게 줄이되 약관 근거를 함께 확인. 확정 전까지 줄이지 않고 그대로 둡니다.
3. 원 미만 처리 방식(D-03 미확정). 카드별 공식 근거 확인 전까지 원 미만이 생기면 확인 필요로 둡니다.
4. 업무 API 명세(수동 카드·상태·주문·예정 소비)와 사용자 식별 방식(D-09). 저장소에 명세가 없어 API 작업을 시작하지 않았습니다.
5. CODEF 공식 개발 문서(developer.codef.io)는 화면을 스크립트로 그려 이 세션 도구로 명세 본문을 읽지 못했습니다. 권장안: 사용할 API(승인내역·보유카드·실적) 명세의 주소·버전을 확인해 주시면 어댑터를 시작합니다.
