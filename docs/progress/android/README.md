# Android 진행 상황

- 작성: 2026-10-28, 기준 `origin/develop` `cbc50fb`
- 상태 구분: 아래 내용은 모두 **작업 브랜치 상태**(#22·#25·#27 각 브랜치)이며 아직 `develop`에 반영되지 않았습니다.

## 지금 가능한 것

- 네이티브 기기 인증: 지문 또는 기기 PIN을 한 인증 창으로 받습니다(D-08). 인증 수단이 없으면 활성화하지 않고 설정 안내를 합니다.
- 60초 활성 상태: 성공 시 60초 활성, 만료·실패·취소·앱 이탈 시 즉시 비활성, 재인증 시 새 60초. 회전 등 화면 구성 변경은 이탈로 보지 않습니다.
- 인증 요청 하나만 진행: 앱 이탈로 취소한 요청은 `정리 중`으로 두고 그 최종 결과가 올 때까지 새 요청을 받지 않습니다. 응답이 없으면 `정지`로 바꾸고 활성화하지 않습니다. **검증용 구현**(커밋 전)입니다. 실기기(SM-S942N 한 대)에서 주요 항목은 관측상 통과했지만 `정리 중` 경로는 관측하지 못했고, 응답 대기 시간 운영 값은 미확정입니다
- 확인 수단: 단위 테스트 83건(가짜 authenticator, 상태 기계·관측 기록 연결 계약만 확인. 2026-10-30 Android 작업자 실행), debug 앱의 **B:ONE 인증 점검** 화면과 debug 전용 관측 로그 `BeoneAuthTrace`(release 미포함)
- 실기기(SM-S942N, Android 17):
  - 구조 도입 전 코드: 확인 목록 1~15번 통과(2026-10-29)
  - 지금 코드(커밋 전): 로그 보강 전 APK로 사용자 화면 관측(2026-10-29~30), 로그 보강 후 APK로 화면 관측과 debug 로그 대조(2026-10-30). R1~R4·R6~R9와 1~6·8~11·13번 관측상 통과. R5·R10은 관측 못 함, 7·12·14 단독·16·17번은 미실행 — [확인 기록](../../android/device-checklist.md#확인-기록-2026-10-2930-지금-코드-커밋-전)
- WebView 셸(#25 브랜치): debug는 개발 서버를 열고 신뢰 origin 밖 탐색을 막습니다. release는 웹 주소 미설정으로 아무것도 열지 않습니다.
- 연결 단계: 기기 인증과 WebView는 서로 연결되지 않았고, 웹 브리지·서버 연결도 없습니다.

## 사용자 확인 사항

1. **release에서 React 화면을 불러오는 방식과 신뢰 origin** — 앱 번들 에셋(`WebViewAssetLoader`, `https://appassets.androidplatform.net`) 또는 원격 주소. 권장안: 앱 에셋 방식(PoC에서 동작 확인, 네트워크 없이 origin 고정 가능). 정해지기 전에는 WebView 작업을 설정값 분리까지만 합니다.
2. **WebView 브리지 계약**(메시지 이름·필드·방향·origin) — 프런트엔드와 함께 정해야 합니다. 초안과 질문 B1~B6은 PR #28에 있습니다. 권장안: `addWebMessageListener` + 신뢰 origin 규칙.
3. **지문 불일치 한 번에 즉시 비활성화** — PRD §4.3-4 문구대로 구현했습니다. 인증 창이 열린 채 다시 시도할 수 있습니다. 권장안: 유지.
4. **실기기 확인 16·17번** — 기기 보안 설정을 바꿔야 하므로 기기 소유자의 판단이 필요합니다. 1~15번은 구조 도입 전 코드로 통과했습니다.
5. **#22 지금 코드의 남은 결정** — 운영 응답 대기 시간 값(실험값 30초에서 PIN 입력을 30초 넘게 끌면 정지됨), 정지 뒤 복구 방식, `정리 중` 경로를 더 관측할지, 커밋 범위.
